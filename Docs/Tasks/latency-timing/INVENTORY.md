## Priority and qualification vocabulary

- **P0:** measurement foundation and the first CPU, REST and interaction slice.
- **P1:** primary bot workflows, cache, client and authoring expansion.
- **P2:** optional service, host, media and cryptographic breadth.
- **Semantic:** injected virtual time, barriers and scripted owners establish
  correctness and ownership, with no numerical performance claim.
- **Local CPU:** optimized executable on a named host; external batch timing for
  pure operations. A normalized batch percentile is not a call percentile.
- **Local I/O:** real loopback sockets/IPC or signed local ingress; peers and
  injected delays are recorded. Scripted transports are separately labeled.
- **Native:** completed runs on the named OS, architecture, SDK and adapter.
  A portable scripted run cannot certify native adapter support.
- **External:** separately invoked desktop/browser, audio hardware or live
  service qualification. Ordinary workloads never imply this level.

The qualification column below specifies the required evidence boundary, not
completed timing evidence. Finite dimension values are the initial representative
selection for future profiles, unless identified as existing profile limits.
Larger sweeps require their own explicit, versioned profile; there is no Cartesian
product requirement. All timed runs include failure, cancellation, rejection and
uncertainty counts where those outcomes apply.

## Historical harness boundaries and report inventory

- [LoadRunner.swift](../../../Tools/DiscordKitLoadTests/Sources/DiscordKitLoadTests/LoadRunner.swift)
  `exchange` begins before assignment and request construction. It awaits
  `poolSlots()` immediately after headers, before body validation/EOF; its final
  elapsed value therefore includes diagnostic actor wait and its scheduling
  effect. A future corrected request identity must move diagnostics after the
  measured endpoint, rather than merely subtracting a separately timed snapshot.
- [HTTPPolicyRunner.swift](../../../Tools/DiscordKitLoadTests/Sources/DiscordKitLoadTests/HTTPPolicyRunner.swift)
  `exchange` begins before endpoint selection/construction, includes the REST
  result and payload validation, then awaits coordinator/cache snapshots before
  the elapsed timestamp. Preserve that historical inclusive meaning and introduce
  a corrected metric/profile version; Stage 0 does not silently edit it.
- `LatencySummary` in the load and DSL tools computes nearest-rank quantiles over
  retained successful/prefix samples. Load collects at most
  `maximumLatencySamples`; DSL samples a bounded prefix before sustained work.
  The existing artifacts cannot become full-run/all-outcome distributions by
  relabeling them. Cache/broadcast has counts and resource/soak observations but no
  operation latency distributions.
- `LoadReport` in [main.swift](../../../Tools/DiscordKitLoadTests/Sources/DiscordKitLoadTests/main.swift),
  `HTTPPolicyReport`, `GatewayLoadReport` and `CacheLoadReport` have no shared
  schema-version envelope. Profile version 1 is a workload-profile version, not a
  shared report schema. Preserve these legacy shapes/readers.
- DSL [DiscordDSLBenchmarks.swift](../../../Tools/DiscordDSLBenchmarks/Sources/DiscordDSLBenchmarks/DiscordDSLBenchmarks.swift)
  explicitly emits schema version 1. It executes direct then DSL in the same
  process; [Measurements.swift](../../../Tools/DiscordDSLBenchmarks/Sources/DiscordDSLBenchmarks/Measurements.swift)
  exposes process-wide gauges and non-Darwin `hardwareModel = unavailable`.
  Some syscall failures currently produce zero CPU/peak RSS; future reports need
  explicit unavailability. Existing baseline/budget scripts retain their v1 input.
- Voice `QualificationReport` currently uses schema version **2**, with separated
  warmup and measured lifetime counters; Apple audio `NativeReport` in
  [Runner.swift](../../../Tools/AppleAudioQualification/Sources/AppleAudioQualification/Runner.swift)
  uses schema version **1**. Neither is the future shared envelope; adapters must
  retain native report/version identity and their distinct qualification scope.
